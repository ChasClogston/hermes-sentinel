# 90-second demo storyboard (synthetic actions only)

**Opening (0–12s):** "Hermes agents can run powerful tools, but tools need enforceable authorization. Hermes Sentinel is an independent, cross-platform action policy plugin."

**Audit mode (12–28s):** Show `HERMES_SENTINEL_MODE=audit`, run `PYTHONPATH=. python demo/hook_smoke.py`. Point to the *observe-only* decisions. Narrate: "Audit mode records policy outcomes without stopping proposed actions."

**Enforcement (28–54s):** Show same terminal output: local `pytest` requires Hermes approval, ordinary external HTTP request produces a Hermes approval directive, and an upload of a synthetic `.env` file is blocked by policy. No actual network command executes in this demo; results are generated by the real Sentinel hook callback.

**Confidentiality (54–70s):** Show the generated audit log. It contains structured verdicts and HMAC identifiers, not commands, URLs, or the synthetic canary.

**Hermes integration (70–82s):** Show an isolated-profile `hermes plugins doctor --ci hermes-sentinel` output confirming one `pre_tool_call` hook and `hermes plugins validate .`.

**Close (82–90s):** "Open-source, audit-first, macOS and Linux, built for Hermes. Sentinel governs proposed tool actions; it is not a network sandbox."

## Demo integrity

Do **not** claim an actual exfiltration attempt was stopped if only passing synthetic proposals to the hook. Label as "simulation" throughout. A live model-driven Hermes run and human approval resolution need additional integration testing.
